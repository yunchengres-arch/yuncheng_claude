# 雲承週報

JAY 每週一（公休日）花 10 分鐘看這份報告，要一眼知道三件事：上週生意比前週好或差、離月目標還差多少、下週該做什麼。所以報告的重點是**結論和行動**，數字是用來支持結論的。

## 一、週的定義

- 一週是**週一～週日**，檔名用該週週一的日期。週一固定公休，所以實際營業日從週二起算。
- 週二是否營業看當月排休（原則上每月休 8 天）。排休表在 `../雲承/店休表.docx`，或使用者告知的店休日。**先確認這週實際營業幾天**，這個數字會影響後面所有比較。

## 二、取得資料

需要的數字，依用途分三組：

| 來源 | 要拿的資料 |
|---|---|
| 點餐後台（POS） | 每日內用營業額與筆數、外帶營業額與筆數；品項銷量（看套餐）；套餐份數以「加價作法」計算，0 元作法是客人的調整，不算套餐 |
| Uber Eats 商家後台 | 每日銷售額與訂單數、商店瀏覽數、瀏覽到下單的比例、廣告花費與廣告帶來的營業額 |
| Google 商家評論 | 本週新增的評論（星等、內容、有沒有回覆） |

### 模式 A：使用者已經提供資料
使用者可能附上匯出檔、貼上數字，或指定資料夾。先把所有提供的檔案讀完再開始算。檔案裡沒有的項目就是缺口，見下方「缺資料」。

### 模式 B：從 Safari 讀後台
使用者沒有給資料時，用 `backend-read` skill 讀後台（Safari 設定、登入失效處理、各來源查法、總額核對與缺口記錄都在裡面）。請 JAY 先自己登入，**登入後一次查完**。

週報要查的範圍：上週與前週（比較用）的每日內用、外帶、Uber 數字，加上本週新增的 Google 評論。各日加總要等於整週總額，對不上就說明差多少，不要硬湊。

### 缺資料
哪個來源讀不到或使用者沒提供，**就在報告裡明說缺什麼，那一塊留白**。不要用估算或上週數字補，也不要把缺的當成 0。這樣做是因為 JAY 會依這份報告做決定，一個編出來的數字比空白更危險。缺口會讓結論的把握度下降，要在結論裡講出來，例如「Uber 數字缺，總額是下限」。

## 三、計算

**營業額口徑**
- 總營業額 = 內用 + 外帶 + Uber 銷售額（未扣抽成）。外帶指客人自己到店取餐，外送指 Uber。
- Uber 另外列「實拿」：抽成目前 15%（自取 0%）。2027-09 起會升到 31%，報告不用提醒，月結時才處理。
- 占比 = 各管道營業額 ÷ 總營業額，同時列出筆數占比，因為外送客單價和內用不同，兩個占比的故事不一樣。
- 客單價 = 營業額 ÷ 筆數，每個管道各算一個。

**每週目標**
- 目標看 `memory-bank/activeContext.md` 最新的記錄：有當月階段目標（例如 12 月 21 萬）就用它，沒有就用長期目標月營業額 30 萬。
- 每週目標 = 月目標 × 本週營業日 ÷ 當月營業日。按營業日分配，是因為休假多的週本來就賣得少，不能拿整月平均直接比。
- 另外列「月累計」：本月到目前為止的營業額，以及要達標，剩下每個營業日要做多少。月累計需要本月前幾週的資料，沒有就留白。

**比較**
- 比較上週、近 4 週平均。**兩週的營業日數不同時，用「每營業日」比較**，並同時列出總額。例如本週休 2 天，總額掉 18% 但每日平均只掉 2%，真正的結論是「生意沒變差，只是少開了」。
- 變化要說明大小和可能原因（推論要標示是推論）。已知的背景在 `memory-bank/progress.md`，例如廣告期間、套餐上線、休假。

## 四、評論

- 只列本週新增的評論，附星等和一句摘要。
- 3 星以下或有具體建議的，另外寫**回覆草稿**。草稿遵守店家口吻：感謝客人、具體回應、不制式。
- 回覆只寫草稿，**不送出**。送出前一定要 JAY 確認，所以草稿要放在報告裡，讓 JAY 一起看。
- 回覆裡提到店內做法時，只用 `memory-bank/productContext.md` 裡 JAY 確認過的（例如主餐可續米線、有套餐、出餐可選直接出餐或桌邊、湯不夠熱可請店員加熱）。

## 五、報告格式

直接用 JAY 的語氣：口語、直接、繁體中文，先講結論。用這個結構：

```markdown
# 雲承週報｜MM/DD–MM/DD（營業 N 天）

## 結論
1. （最重要的發現，一句話＋數字）
2.
3.

## 數字
| | 本週 | 上週 | 變化 | 每營業日 |
|---|---|---|---|---|
| 總營業額 | | | | |
| 內用 | | | | |
| 外帶 | | | | |
| Uber 外送 | | | | |
| 筆數 | | | | |
| 客單價 | | | | |

## 內用／外帶／外送占比
（營業額占比和筆數占比，與上週比較）

## 目標進度
本週目標 X、實際 Y（Z%）；月累計 A／月目標 B；要達標每個營業日還要 C。

## 評論
（新評論摘要；需要回覆的附草稿，標明「待 JAY 確認，尚未送出」）

## 下週行動（建議，由 JAY 決定）
1.
2.

## 資料缺口與口徑
（缺哪些資料、哪些數字是推論或下限、營業日怎麼算）
```

下週行動最多 3 項，每項要具體到 JAY 看了就能做，並說明對月目標的貢獻（每天多幾位客人、每月多多少元）。改價格、改菜單、調廣告預算、對外發文都只能寫成建議，不能自己做。

## 六、存檔與記錄

- 存到 `雲承營業分析/週報_YYYY-MM-DD.md`（日期為該週週一）；使用者指定別處就照指定。
- 完成後在 `memory-bank/progress.md` 加一行：日期、本週總額、目標達成率、一件需要追蹤的事。
- 回覆時先講三個結論，再告訴 JAY 檔案位置。不要把整份報告再貼一次。
