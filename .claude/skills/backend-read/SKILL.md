# 讀取雲承後台資料

雲承的後台都沒有現成的 API，資料要靠 JAY 已經登入的 Safari 讀出來。這些數字會直接拿去做決策（週報、月結、調價、廣告），所以三件事比速度重要：**總額要核對、缺口要記下來、讀不到就說讀不到**，絕不編造或用舊資料補。

## 一、前置與界線

- Safari 要開啟「開發 → 允許來自 Apple Events 的 JavaScript」（選單沒有「開發」就先到 Safari 設定 → 進階，勾選「顯示網頁開發者功能」）。沒開就請 JAY 開。
- **登入由 JAY 自己做**。不代填帳號、密碼或驗證碼，也不要把 cookie、token 抄下來存檔。
- **只讀，不點任何會改變狀態的東西**：下單、處理訂單、改價格、改廣告、改營業狀態、送出評論回覆，都不在這個 skill 的範圍。送出評論回覆是另一個 skill（`review-reply-post`），而且要 JAY 先確認。
- 用**新分頁**讀，不要把 JAY 正在看的分頁導走。讀完告訴 JAY 你開了哪些分頁。

## 二、怎麼讀

JavaScript 內容寫成檔案，再讓 AppleScript 讀檔執行。直接把長 JS 放在 `osascript -e` 裡，引號會出錯。範本：

```applescript
on run argv
  set js to read POSIX file (item 1 of argv) as «class utf8»
  tell application "Safari" to return do JavaScript js in current tab of front window
end run
```

- 讓 JS 回傳 `JSON.stringify(...)`，再用 `python3 -I` 解析。這台電腦的 Python 是 3.9，沒有 openpyxl。
- 頁面是動態載入時，先捲動內層可捲動的區塊再讀；讀完用筆數核對，確定有載入完。

## 三、登入失效要先處理

點餐後台的登入狀態常在幾分鐘內失效。下面任何一種情況，都視為「沒有讀到資料」：
- 回傳的是登入頁（HTML 裡有密碼欄位或「登入」）、401／302，或空白。
- 數字突然全是 0，而你預期有營業。

遇到時**立刻停止**，告訴 JAY：後台登出了，請重新登入。不要用舊資料或上個月的數字補，不要猜。重新登入後，**先把要查的所有請求列好，登入後一次查完**，這樣才不會查到一半又登出。

## 四、各來源

**點餐後台**（`fcdmc.com.tw:8989`）
- `POST /orderCalculate.do`，日期欄位 `begindate`、`enddate`。品項統計用 `tasteCalculate=0`；要看 0 元作法用 `tasteCalculate=2`。
- 取餐方式用 `typeSearch`。總額查詢（`typeSearch=1`、`tasteCalculate=0`）曾核對過十月是 187,215，是**全部取餐方式的合計**（內用 175,240、外帶 11,975）。`typeSearch` 各值對應哪種取餐方式還沒完全確認，所以先查總額，再分別查內用與外帶，三者要加得起來。
- 品項合併規則：奶茶、高山青茶、涼拌米線改名視為同品項；「作法：A+B」維持獨立；同名重複列併入主餐。**套餐＝加價作法**，0 元作法是客人的調整，不算套餐。

**Uber Eats 商家後台**
- 要讀：銷售額、訂單數、抽成（目前 15%，自取 0%）、商店瀏覽數、瀏覽到下單的比例、廣告花費與廣告帶來的營業額。
- 訂單明細常分頁或只載入一部分。**同時記下「明細筆數」和「後台摘要筆數」**，兩者不同就是資料缺口，要寫出來（曾發生摘要 133 筆但只讀到 130 筆）。
- 明細裡有客人的姓名、地址這類個資，**不要寫進專案檔案**，只保留彙總。

**Google 商家評論**
- 商家面板的評論頁是 iframe（網址含 `customers/reviews`）。從 iframe 的 `src` 取出網址，在新分頁打開再讀。
- 切到「未回覆」、捲動內層容器載入全部、點開所有「查看完整評論」。
- 每則評論的星等在 `aria-label="N 顆星 (滿分 5 顆星)"`，往上找到只含這一則的容器，再讀裡面的文字。
- 評論作者的名稱是公開的，可以寫進草稿檔；但不要整頁複製存檔。

## 五、驗證與輸出

- **各日加總必須等於期間總額**。對不上時，寫出差多少，**不要調整任何數字去讓它對上**。例如十月品項加總和內用營業額曾差 10 元，如實記錄。
- 內用 + 外帶 要等於 POS 總額；POS + Uber 才是整體營業額。
- 輸出整理成表，並寫明：期間、查詢時間、來源、驗證結果、缺口（缺哪幾筆、哪幾天、哪個欄位沒讀到）。
- 原始回傳只放暫存位置，不放進專案資料夾。
- 讀完後告訴 JAY：讀到什麼、核對結果、缺什麼。缺的就是缺的，留白。
