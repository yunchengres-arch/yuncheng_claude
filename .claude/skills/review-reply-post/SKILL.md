# 送出 Google 評論回覆

評論回覆是以店家名義**公開發表**的，送出後很難收回，客人和潛在客人都看得到。所以這個 skill 的核心是：**只送 JAY 確認過的，送完逐則驗證**。草稿由 `review-replier` agent 或主對話寫好，這個 skill 只負責送出。

## 一、送出前的確認（缺一不可）

1. 草稿檔存在（通常是 `行銷文案/Google評論回覆草稿_*.md`），每則有編號、客人名稱、原評論和回覆內容。
2. **JAY 在這個對話裡明確說可以送出**（例如「可以回覆」）。草稿寫好但 JAY 還沒說可以，就不送。之前的批准只適用於當時看到的那一版，**草稿在批准後又被改過，要重新確認**。
3. 排除這幾種，不要送：
   - 標「不回覆」或「不處理」的。
   - 標「待 JAY 確認」、「請 JAY 決定」、⚠ 的，除非 JAY 已經處理並移除標記。
   - 提到補償、折扣、贈品而 JAY 沒有確認過的。
4. 先列出「這次要送的清單」（編號、客人、回覆前 20 字）和「不送的及原因」，再開始。

沒有 Safari 可用，或 JAY 說「先模擬」時，只輸出上面的清單，不送。

## 二、送出流程

資料讀取的基本做法（Safari 設定、JS 寫成檔案、登入由 JAY 負責）見 `backend-read` skill。

1. 在新分頁打開評論 iframe 的網址（網址含 `customers/reviews`），點「未回覆」，捲動載入全部，必要時展開被截斷的評論。
2. **先只送第 1 則**，重新整理確認它真的消失在「未回覆」清單，流程確定正常才送其餘的。
3. 每一則：
   - 用客人名稱找到那一則的卡片。名稱要**完全相符優先**，其次才是開頭相符。名稱重複或很像時，加上星等、時間和評論開頭一起比對，**找不準就跳過並回報，不要猜**。
   - 點該卡片的「回覆」，在 `textarea[aria-label="你的公開回覆"]` 填入內容。要用原生的 value setter，再觸發 `input`、`change` 事件，頁面才會認得。
   - 點該區塊裡的「回覆」按鈕送出，**等 8 秒以上**，不要連續快速送。
4. 全部送完後，**重新整理頁面**，再切到「未回覆」、捲動載入全部，逐一檢查這次送的每位客人是否都不在清單裡。畫面當下顯示消失並不可靠：用 4 秒間隔送過 59 則，有 4 則看起來送出了，重新整理後其實還在。
5. 還在清單裡的，**放慢速度重送**（間隔加長），再重新整理驗證，直到全部確認，或回報哪幾則失敗。
6. 同一則不要重複送，重送前先確認它真的還在「未回覆」。

## 三、送完之後

- 在草稿檔最上方記錄：送出日期、實際送出幾則、不回覆幾則、失敗幾則。
- 在 `memory-bank/progress.md` 加一行：日期、送出數量、不回覆的原因、剩下未回覆的數量。
- 告訴 JAY：送了幾則、驗證結果、哪幾則沒送以及原因。不要把回覆全文再貼一次。
- 送出的內容與草稿**一字不改**。覺得要修改，先問 JAY。
