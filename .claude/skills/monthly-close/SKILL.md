# 雲承月結

JAY 每月初用這份月結看上個月到底賺不賺錢、離目標多遠、哪裡在失血。這個專案的營運表手工填寫、公式也有過錯誤，所以月結的重點是：**先核對，再下結論**。沒核對就算出來的損益，可能差好幾千元，會讓 JAY 誤判。

詳細的核對清單與報告格式寫在 `.claude/agents/finance-analyst.md`。月結時先讀它，並照它的核對清單和報告格式做。如果可以呼叫 subagent，核對與分析可以交給 `finance-analyst`；否則自己照做。

## 流程

### 1. 確認月份與口徑
- 結算哪個月（通常是上個月）；月初到月底完整的一整月。
- 目標：看 `memory-bank/activeContext.md`（階段目標或長期 30 萬）。

### 2. 取得資料
- 點餐後台、Uber 後台：用 `backend-read` skill 讀（需要 JAY 先登入）。使用者已經提供檔案或數字時，直接用，不用再讀。
- 營運表、損益平衡試算表、成本表：讀專案裡的 Excel 或 CSV。
- 缺資料就列成待辦，**不要估算補上**。進貨單、庫存盤點只有 JAY 手上有。

### 3. 核對（損益算出來之前先做）
照 finance-analyst 的清單逐項檢查，特別是這幾個過去真的出過錯的地方：
1. 月初庫存是否等於上月月底庫存。
2. SUM 公式範圍有沒有漏欄位。
3. 同一筆費用有沒有在兩個分頁都進總計（例如瓦斯）。
4. 貸款、小額耗材有沒有漏列。
5. 損益表營業額是否等於 POS 加 Uber。
6. Uber 抽成率是否是現行 15%（不是舊的 35%）。
7. 空白欄位不一定是 0，要註明。

發現錯誤時寫出：檔案、分頁、儲存格、錯多少、對損益影響多少。

### 4. 更新與修正
- **原檔不動。** 在「_修正版」副本裡更新品項銷售、營運表、損益平衡試算表。Excel 被開著時資料夾會有 `~$` 開頭的暫存檔，要請 JAY 先關檔。
- 列出所有更動的儲存格和原因。

### 5. 計算
- 營業額 = 內用 + 外帶 + Uber 銷售額；Uber 另列實拿（扣 15% 抽成）。
- 食材成本 = 月初庫存 + 本月進貨 − 月底庫存（用核對後的庫存）。
- 損益**一定列三個版本**：① 不扣老闆薪資、不含貸款；② 扣老闆薪資（50,000＋健保 2,641＝52,641）、不含貸款；③ 扣老闆薪資、含貸款（月付 36,000）。只列一個版本會誤導 JAY。
- 和上月、和月目標比較；若是核對前後數字不同，兩個都要寫，說明差在哪。

### 6. 報告
存到 `雲承營業分析/月結_YYYY-MM.md`，格式照 finance-analyst 的月結報告：先 3 點結論（含三個版本的損益），再依序損益表、目標進度、品項與毛利、外送、發現的錯誤與修正、下月行動（最多 3 項，建議由 JAY 決定）、資料缺口與口徑。用繁體中文、口語。

### 7. 記錄與交付
- 在 `memory-bank/progress.md` 加一行：月份、營業額、三個版本的損益、發現的錯誤。
- 回覆時先講 3 個結論，再告訴 JAY 報告和修正版檔案的位置，並列出需要他補的資料。不要把整份報告再貼一次。
- 改價格、調薪、貸款安排，只能寫成建議。
